# Phase 4：Agent 协作与智能推荐

## 1. 目标

让 Agent 扩大玩法采矿、分析和内容生产效率，让推荐系统在稳定数据基础上学习用户、场景和内容之间的关系。Agent 和模型都不能绕过人工发布控制。

## 2. Agent 任务类型

### 采矿任务

输入来源类型、地区、语言、人数和道具约束，输出原始玩法样本。必须保留原始名称、来源链接、原始规则和证据级别。

### 机制分析任务

输入原始样本，输出核心互动、信息结构、控制结构、L0 候选、相似样本和不确定点。分析结果是提案，不是最终分类。

### L1 归并任务

把多个样本聚类，提出一个 L1 或一个 L1 变体。必须说明保留了什么、去掉了什么、为什么不是已有 L1 的 L2。

### L2 内容任务

按照 L1 的 `content_type` 生成题目、故事、尺度或选择项。输出必须符合 JSON 结构、字数限制、敏感度规则和内容来源要求。

### 低表现分析任务

基于 L1/L2 指标、事件序列和试玩笔记，提出可能原因和修改建议。Agent 不能直接把低表现归因于玩法本身，必须列出卡面、场景、内容难度和流程摩擦等替代解释。

## 3. Agent 提案格式

每个提案至少包含：

```text
proposal_id
task_id
entity_type
parent_entity_id
proposed_payload
source_evidence
change_summary
playbit_fit_reason
risk_note
test_plan
model_name
model_run_id
```

提案必须支持字段级差异比较。只展示 Agent 的总结不够，审核人员需要看到原值、新值和证据。

提案自身使用独立生命周期，不跟任务状态混用：

```text
OPEN → IN_REVIEW → ACCEPTED / REJECTED / SUPERSEDED
```

一个 Agent 任务可以产生多个提案；任务成功不等于提案被接受。接受提案时必须记录解决人、解决时间、目标 L1/L2 版本和生成的新版本号。被拒绝或被替代的提案保留，不能覆盖成最新结果。

## 4. 人工审核闸门

### 机制闸门

- 是否存在明确的行动循环。
- 玩家是否知道下一步做什么。
- 胜负或结束条件是否可判断。
- 是否过度依赖主持人临场发挥。

### Playbit 闸门

- 是否能快速开始。
- 是否适合碎片社交。
- 是否需要专用道具或大空间。
- 是否容易尴尬或让人被迫暴露隐私。
- 卡面是否能在一屏内讲清。

### 运营闸门

- L2 是否能持续供应。
- 内容是否适合冷却和重复策略。
- 是否有足够的变体空间。
- 是否存在版权、安全或适龄问题。

### 试玩闸门

- 是否自然开始。
- 是否少解释。
- 是否中途卡住。
- 是否想再来一局。
- 参与者是否主动产生新的内容。

## 5. Agent 状态和权限

```text
QUEUED → RUNNING → SUCCEEDED
                 └→ FAILED
QUEUED → CANCELLED
```

Agent 可以创建 RAW、L1 和 L2 草稿或提案。Agent 不能将内容状态改为 `PUBLISHED`，不能删除正式版本，不能直接修改用户偏好、分发权重或实验结果。

Agent 任务需要限制并发、记录模型版本、保存输入约束和输出摘要。失败任务可以重试，但重试必须生成新的运行记录，不能覆盖历史输出。

## 6. 智能推荐演进

### 第一层：规则排序

继续使用 Phase 3 的候选过滤、L1 偏好、内容新鲜度、疲劳度和探索权重。它是所有模型的保底方案。

### 第二层：统计学习

对开始率、完成率、再玩率和跳过率做平滑估计，避免低曝光内容因为偶然一次失败被直接淘汰。L1 和 L2 分开估计。

### 第三层：上下文推荐

使用人数、场景、入口、时间段、历史收藏、近期跳过和上一张卡等上下文，对候选进行排序。上下文只改变排序，不能突破永久消耗、安全和审核限制。

### 第四层：探索与利用

引入小流量探索或 Bandit，让新 L1 和新 L2 获得可控曝光。探索必须有预算、实验分组、回滚和安全过滤。

模型输出必须保留：策略版本、候选集合、最终选择、主要特征和推荐原因。

每次线上抽卡还要在卡片实例上保存策略版本、实验变体和有限候选快照，保证运营人员能解释“当时为什么选到这张卡”。候选快照只保存候选 ID、过滤原因和分数，不保存聊天原文或完整用户画像。

## 7. 推荐实验

实验可以比较：

- 不同候选过滤规则。
- 不同冷却策略。
- L1 优先和 L2 优先的排序方式。
- 探索比例。
- 卡面文案版本。

实验主要观察自然开始率、完成率、再玩率、重抽率、分享率和负面反馈。不能只用停留时间作为成功指标。

实验需要支持：固定分组、实验起止时间、样本范围、指标定义、最小样本量、提前停止规则和结果备注。

## 8. 当前不应该做的事情

- 不要让 Agent 自动发布。
- 不要在数据很少时训练复杂深度模型。
- 不要把用户跳过一次理解成永久不喜欢。
- 不要用总热度覆盖场景和内容消耗规则。
- 不要把推荐模型特征直接写进 L1/L2 内容实体。
- 不要保存不必要的聊天原文来训练推荐。
- 不要让实验组绕过安全、版权和人工审核。

## 9. Phase 4 验收

- Agent 可以接收约束并创建带证据的提案。
- 人工可以比较提案与原版本并作出决定。
- Agent 失败、重试和历史输出可追踪。
- 推荐策略可以灰度、实验和回滚。
- 新内容获得可控探索曝光。
- 推荐结果可以解释主要原因。
- 模型不会绕过内容生命周期、用户消耗和安全规则。
- L1、L2、场景和实验指标可以分别复盘。
