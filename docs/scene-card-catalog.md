# 场景卡内容试验 · 2026-10-29

这批 30 张卡先在 React Player 本地内容流中体验，没有发布到内容数据库。目标是验证「真实处境 → 内容期待 → 翻面互动」，而不是把同一段通用规则换上不同场景名。

## 创作结构

- 从正在发生的事出发：等车、洗碗、约会、饭后、刚认识、睡前、家庭聚餐和小店活动。
- 内容面本身值得看、听或猜，规则面接住预告。图像、声音、视频是共同题面，不是装饰背景。
- 明确第一步、轮流方式、结束条件；给具体问题、开场句、禁词或素材，减少现场组织和出题压力。
- L0 是互动机制，L1 是可复用玩法骨架，L2 是具体题面与场景适配。`src/data/catalog/gameplays.ts` 保留旧玩法来源；每张草稿的 `l1`、`adaptation`、人数和时长属于创作元数据，不挤进用户卡面。
- 不强行给每张卡分胜负。共创、默契和表达类内容也能自然结束；彩头仍由用户自行决定。

## 媒体与运行

- 资源：`apps/player/public/media/cards/`，8 个资源合计 132,859 字节。WebP 图片、AAC 声音、H.264 faststart 视频，无外链媒体和新播放器依赖。
- 来源：原创程序绘制的游戏插图、动画和合成声音，非照片或 AI 生图。生成器 `scripts/build-scene-card-media.py` 需要 Python 3、Pillow、imageio-ffmpeg；清单 `manifest.json` 记录出处及大小。
- 换杯视频有四次交换，球最终在中间；同一视频支持追踪位置和统计交换次数两种 L2。生成器校验各阶段目标杯位置，规则面的答案默认折叠。
- 音频/视频不自动播放；相邻预渲染卡不设置媒体地址。翻面、换卡、离开页面停止，页面切入后台暂停。音频直接点频谱播放，再点停止；失败提供重试。
- 长文在短屏可在当前卡内滚动，底部翻面和彩头操作固定可达；短屏媒体卡收紧排版以展示完整主素材。

## 保留与待议

- 保留旧卡 ID 供已有收藏、彩头、约定和权益记录继续解析；旧样例不进入新的官方场景。未重置浏览器数据，也没有写入后端。
- 本轮未接 AI 生成、投稿、推荐、商家奖励和广告追踪。现有「AI 组局」依旧只是已有场景匹配，界面如实说明。
- 数据库接入时应单独制定创作草稿到现有导入模板/内容快照的适配，不把当前前端草稿格式冒充可直接入库的模板。
- 文学引用公开发布前需要核实来源与授权；当前按用户原文制作体验稿，不添加未经核实的作者归属。
