# 合约流程逻辑复查

检查范围：创建、登录接续、返回修改、邀请签署、状态同步、加码、结果登记、卡券核销、翻盘、赖皮券与删除。沿用双方自行约定、平台仅记录的边界，不增加平台裁判或强制履约。

## 本轮修复

| 场景 | 原问题 | 修复后的行为 |
| --- | --- | --- |
| 空白自定义权益 | 选择器把占位文字当成实际内容，创建校验可能放行 | 公共选择器输出真实空值，合约/游戏/加码使用实际内容校验 |
| 表单长度 | 前端允许写完签署后才被后台拒绝 | 约定 48 字、权益 80 字，与接口一致，错误就近显示 |
| 创建重试 | 同一创建断网重试或快速双击可能产生两份 | 提交前加锁；同一次尝试携带 UUID，后台按账号与尝试标识幂等创建 |
| 草案修改、乙方签署 | 服务器只检查提交时最新状态，未验证用户实际看过的版本 | 修改、签署必须携带 revision，变更后要求重新查看；抢签失败不返回另一位签署人的文档 |
| 登录接续 | 登录期间合约更新，旧签名可能自动签到新内容上 | 保留原签署版本；版本不变自动继续，变化则显示新文档并提示重新确认 |
| 私密邀请重开 | 已签署邀请在未登录设备上直接显示不可用 | 引导登录后恢复原邀请与参与者页面 |
| 返回创建 | 乙方已签署后仍返回不可编辑草案，反复提交失败 | 未签署可以返回编辑原 ID；已签署不再返回创建页 |
| 长加码 | 基础权益与三次加码可达 323 字，但卡券序列化只允许 80 字 | 卡券承载完整合并权益；单次输入限制仍为 80 字 |
| 非法状态加码 | 待签署/已结算加码触发服务器异常 | 明确返回状态冲突；空白加码返回输入错误；提交中禁重复操作 |
| 客户端越权状态 | 创建/修改请求可带入“已履约”及伪造的确认加码 | 请求模型拒绝这些服务端状态，不能提前写入资产事实 |
| 状态同步 | 旧合约请求可能抢回当前页面，旧列表可能覆盖新版数据或恢复退出账号数据 | 校验当前账号、合约 ID 和 revision；保留请求期间新建记录；忽略已删除记录 |
| 网络失败 | 暂时离线清除登录凭据或把已有卡券清空 | 仅确认身份失效时清除凭据，临时错误保留已加载资产；手动刷新失败给提示 |
| 结果响应丢失 | 后台已登记成功，页面仍可能留在原步骤 | 同步恢复同一结果后进入结算，不重复发行卡券 |
| 核销与翻盘同时发生 | 内存实现可能先改合约状态，再发现券已被另一操作占用 | 先占用同一张券，失败恢复，保证只有一个动作取得权益 |
| 删除竞态与关联数据 | 刚完成的合约可能被旧请求删除；内存库遗留关联数据；申请中赖皮券永久占用 | 终态合约直接拒绝删除；可删除记录校验 revision，并同步清理关联卡券/翻盘/申请，释放申请中赖皮券；PostgreSQL 中与删除同事务 |
| 对方页面已被删除 | 页面仍展示旧合约并持续请求 | 删除事件通知参与者，清除本地关联记录并返回首页；404 同步也能收敛 |

## 本轮已确认并落实

1. **结算后不可删除。** `result_recorded`、`fulfilled` 和 `waived` 均视为终态，历史与已产生权益保留；只有待签署、待加入或进行中的记录可以由发起人删除。
2. **自定义权益发行卡券。** 合约里的 `custom` 与预设 `coupon` 统一走卡券发放、核销、翻盘和赖皮券机制；积分仍只做记录。
3. **未确认加码可撤回。** 加码发起人可以直接撤回未确认项目，释放次数；一旦双方确认就不能撤回。并发确认与撤回由 revision 冲突保护。

## 仍需产品决定

1. **邀请接收者的身份。** 当前是持链接且最先确认的非甲方账号加入，没有预先绑定某个乙方；并发已保证只加入一人，但误转链接仍可能被他人先签。轻流程下可保留此规则；如要支持“指定乙方”，需另定邀请身份方式，不应临时加房间或复杂审批。

## 验证与边界

- 新增 API 合约回归：创建重试/并发、旧版修改和签署、抢签隐私、伪造权益、长加码、状态边界、删除清理/占券释放、核销与翻盘互斥。
- 新增前端 21 项回归：真实空输入、长度限制、登录接续、请求幂等、返回路径、旧响应隔离、签署后加载期间退出登录、终态删除限制、加码确认与撤回；纳入根目录 `pnpm test`。
- 浏览器实测自定义权益留空时在输入框下方提示，不能进入签署；未向运行中的服务提交测试合约。
- 原有游戏、权限、卡券、翻盘、赖皮券测试继续执行。
- API 自动化使用独立内存仓库，不修改运行中的用户数据。PostgreSQL 分支通过类型检查和事务代码审查，但本轮未连接实际 PostgreSQL 执行并发压测；真实多设备弱网仍需发布前验证。
- 本轮接口要求创建 requestId、修改/签署 revision，前后端需同步发布，不提供旧接口形状兼容。
